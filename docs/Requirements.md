# GoScrapy — 分布式高可用智能爬虫集群与可视化规则提取平台

> **文档性质**：SSOT（唯一真相源）。本文件定义 **WHAT**，`docs/Roadmap.md` 定义 **WHEN**。
> **状态**：需求已冻结（Frozen）
> **评审**：PM Agent · Alkaid-SOP v13.0
> **时间**：2026-08-22 (GMT+8)

---

## 1. 项目定位

一句话定义：**一个可通过 Web 界面管理爬虫节点、在浏览器中点选网页元素即可自动生成抓取规则、并以分布式布隆过滤器保证海量 URL 不重复抓取的自托管数据采集平台。**

它不是一个爬虫脚本，而是三个能力的合体：

1. **集群** — Master 调度 + 多 Worker 横向扩展，节点崩溃任务不丢。
2. **可视化** — 所见即所得地生成 XPath/CSS 规则，无需人工写选择器。
3. **可观测** — 实时大屏呈现各节点负载、抓取速率与失败率。

### 2.2 关于"外部依赖"的判定说明

爬虫的抓取目标看似是外部依赖，但它抓取的是**页面结构**而非实时事实数据（不同于股价、赛事比分这类无法用 Mock 有意义替代的场景）。因此本项目自建容器化 Mock 目标站点，该站点不是权宜之计，而是架构必需品——它同时解决了 §3.2 的跨域硬阻断问题。

## 3. 需求矛盾裁决记录（★ 关键章节）

原始需求存在 7 处技术矛盾。其中 **C-1 与 C-2 属于硬阻断**：若按字面实现，功能根本无法工作。以下裁决为最终决定，后续阶段不得推翻。

### C-1 「Vue 3 + Chrome DevTools 协议嵌入」在前端不成立 🔴 硬阻断

**冲突**：CDP 是通过 WebSocket 控制 Chrome 渲染进程的调试协议。运行在浏览器沙箱内的 Vue 应用没有任何权限去附加（attach）到另一个网站的渲染进程上。前端无法使用 CDP。

**裁决**：CDP 能力下沉到 Go 后端。

- 后端通过 `chromedp` 驱动独立的 `headless-shell` 容器加载目标页；
- 后端产出**三元组**回传前端：`页面截图(PNG)` + `DOM 结构树` + `每个可见元素的盒模型坐标(BoxModel)`；
- Vue 端在截图之上叠加一层透明可点击热区，热区位置由盒模型坐标驱动；
- 用户点击热区 → 前端回传 `nodeId` → 后端在 DOM 树上计算选择器并返回候选列表。

用户所要的"点击网页元素自动生成选择器"体验被 100% 保留，只是渲染与计算发生在服务端。

### C-2 iframe 内嵌任意目标网页并读取其 DOM，被浏览器安全策略硬性阻断 🔴 硬阻断

**冲突**：绝大多数站点响应头带有 `X-Frame-Options: DENY` 或 CSP `frame-ancestors 'self'`，iframe 直接加载失败；即便加载成功，同源策略也使跨域 iframe 的 DOM 对父页面 JavaScript 完全不可读，无从计算 XPath。

**裁决**：**放弃 iframe 方案**，统一走 C-1 的服务端快照方案。Mock 目标站作为同源演示通道兜底，保证离线可完整验收。

### C-3 「按 URL 哈希静态切分」与「动态分发 + 高可用」自相矛盾

**冲突**：静态哈希分片在 Worker 上下线时会产生分片归属漂移、热点倾斜与任务滞留，与"动态分发"和"高可用"目标直接对立。

**裁决**：任务流与控制流分离。

- **任务分发**：Redis 优先级队列 + **Worker 主动 Pull + 任务租约（Lease）**。天然负载均衡；Worker 崩溃后租约超时，任务自动重入队。
- **URL 哈希保留两项正当用途**：(a) 布隆过滤器分桶键；(b) **同域名亲和性路由**——保证同一站点的限速计数与 Cookie 复用落在单个 Worker 内生效。
- **gRPC 承载控制流**（Master ⇄ Worker 双向流）：下发规则变更、限速调参、优雅停机、上报心跳与指标。任务体不走 gRPC，避免其成为吞吐瓶颈与单点。

### C-4 声称「分布式高可用」但 Master 是单点

**裁决**：Master 设计为**完全无状态**，全部状态落于 Redis 与 PostgreSQL，允许多副本运行。多个 Master 实例通过 Redis 分布式锁选主，仅主实例执行调度循环，非主实例照常提供只读 API。故障切换 SLA 见 §6。

### C-5 「智能」一词边界模糊，存在范围漂移风险

**裁决**：本项目的"智能"严格限定为两项**确定性算法**能力，**MVP 与 V1 均不引入 LLM**：

1. **选择器智能推导** — 按优先级 `id` > `data-*` 测试属性 > 全局唯一 class > 属性组合 > 结构化 `nth-child` 路径 逐级降级；并对兄弟节点做结构相似度聚类，自动把"单元素选择"泛化为"整列表抓取规则"。
2. **自适应限速** — 依据响应码分布（429/403 占比）与响应时间滑动窗口，动态调整每域 QPS 与代理轮换策略。

LLM 辅助抽取列入 V2 可选项，**默认关闭**；若启用必须走 Mock Provider 并在 `README.md` §7 记录开关。

### C-6 容器内 CPU/内存指标失真

**冲突**：`gopsutil` 在容器内默认读取宿主机 `/proc`，导致监控大屏显示的是宿主机负载而非节点负载，监控失去意义。

**裁决**：指标采集读取 cgroup v2（`/sys/fs/cgroup/memory.current`、`cpu.stat`）计算容器实际用量，compose 中以只读方式挂载 `/sys/fs/cgroup`。

### C-7 爬虫合规性未提及

**裁决**：默认开启 `robots.txt` 遵守与可识别 User-Agent 标识；默认抓取目标为自建 Mock 站。合规开关可在规则级关闭，但关闭动作必须落审计日志。

## 6. 非功能需求与可量化验收基线

> 以下为**可测量**的验收标准，非描述性文字。QA 阶段逐条验证。

| 维度 | 基线 | 测量方法 |
|---|---|---|
| 去重容量 | 1,000 万 URL，误判率 ≤ 1%（位图约 11.4 MB，k=7） | 灌入 10 万 URL 统计误判计数 |
| 去重延迟 | 批量判重 p99 < 5 ms | Redis pipeline 压测 |
| 抓取吞吐 | 2 Worker 对 Mock 站合计 ≥ 120 pages/min | 大屏速率读数 + 结果表计数 |
| 任务零丢失 | 强杀任一 Worker，任务最终完成率 = 100% | `docker kill worker-1` 后比对总数 |
| 故障重入队 | 租约超时 ≤ 30 s 后任务被其他 Worker 领取 | 队列监控 + 日志时间戳 |
| Master 故障切换 | ≤ 15 s 恢复调度，队列零丢失 | 杀主实例后观测调度恢复 |
| gRPC 指标流 | p95 < 50 ms | 上报时延埋点 |
| 选择器质量 | 生成的选择器唯一命中率 100%；列表泛化命中 ≥ 10 条 | 规则配置器实测 |
| 大屏实时性 | 推送间隔 ≤ 3 s，指标端到端延迟 ≤ 5 s | 前端时间戳比对 |
| 限速精度 | 配置 QPS=2 时实测偏差 ≤ ±10% | 抓取日志时间序列统计 |
| 跨平台 | ARM64 + AMD64 均可构建运行 | `docker build --platform` 双架构 |
| 测试成本 | 每轮 QA 花费 **¥0** | 全 Mock 模式，禁止计费 API |

**基线依据**：布隆过滤器参数按标准公式 m ≈ -n·ln(p)/(ln2)² 推算，1e7 条 @ 1% 得 ≈ 9.585 bit/key ≈ 11.4 MB，最优 k=7。吞吐基线取每 Worker ≥ 1 页/秒的保守值，留出限速与解析开销余量。

## 8. 交付标准（Redline 合规）

### 8.1 Docker 交付

单命令启动：`docker compose up --build -d`，无任何手工步骤。所有基础镜像须支持 **ARM64 + AMD64**。

**服务清单**（开发期使用随机端口，`/deploy` 阶段统一改为 8081+）：

| 服务 | 说明 |
|---|---|
| `postgres` | 规则 / 任务 / 结果 / 节点元数据 |
| `redis` | 任务队列 · 布隆位图 · 租约 · 选主锁 |
| `master` | REST API + WebSocket + gRPC Server + 调度器 |
| `worker` ×2 | 抓取执行节点（副本数 ≥2，用于验证分布式与故障转移） |
| `renderer` | headless-shell，服务于可视化规则配置器 |
| `mock-target` | 自建抓取目标站（静态电商/资讯页） |
| `frontend-admin` | Vue 3 SPA（nginx 托管） |

统一设置 `TZ=Asia/Shanghai`，所有时间按 **GMT+8** 记录与展示。

### 8.2 目录结构

```
backend/          Go 单仓（master 与 worker 共享内核，双入口）
frontend-admin/   Vue 3 管理平台
mock-target/      模拟抓取目标站
docs/             SSOT 文档
```

### 8.3 Mock 合法性声明（Redline 4）

本项目所有 Mock 均满足**双条件合法标准**：真实实现路径已接通，且 Mock/真实切换在 `README.md` §7 显式记录。

| Mock 项 | 真实路径 | 切换方式 |
|---|---|---|
| 抓取目标站 | 任意公网 URL | 任务表单直接填写真实 URL 即可 |
| 代理 IP 池 | 真实代理服务商地址 | 环境变量 `PROXY_POOL_MODE=mock\|real` + 代理列表配置 |
| LLM 抽取（V2） | 真实模型 API | `LLM_ENABLED=false` 默认关闭 |

**禁止**：以 Mock 静默替代真实逻辑且无文档开关——该行为构成造假，触发 STOP。

## 10. 风险登记册

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| headless-shell 在 ARM64 上内存占用高 | 中 | 已验证双架构可用；限制并发标签页数，设置容器内存上限 |
| 服务端快照的坐标与前端叠加层错位 | **高** | 统一以 CSS 像素与固定视口(1440×900, DPR=1)渲染；Phase 1 先做坐标对齐验证 |
| 布隆过滤器不可删除条目导致长期膨胀 | 中 | 按任务维度分 key 命名空间，任务归档时整键回收 |
| 多 Master 选主脑裂 | 中 | 锁带 TTL 与 fencing token，调度前校验持锁有效性 |
| 前端大屏高频推送导致渲染卡顿 | 低 | 服务端聚合后按 ≤3s 节流推送，图表增量更新 |
